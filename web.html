Cómo usar esta página

Para el equipo de LABITCONF. Esta pantalla permite revisar y publicar los speakers de la web.

PASO 1 — ACTIVAR MODO STAFF

Hacé clic en el botón 🔒 Modo staff en la esquina superior derecha. Cuando está activo, aparece un toggle verde Publicar / Publicado en cada card de speaker.

PASO 2 — MARCAR SPEAKERS COMO PUBLICADOS

Activá el checkbox de cada speaker que debe aparecer en la web pública. El cambio se guarda automáticamente en Google Sheets en tiempo real. No hace falta recargar la página.

El estado se guarda en la columna landing del sheet (columna AK). Valor si = publicado, vacío = no publicado.

PASO 3 — VER SOLO LOS PUBLICADOS

Usá el filtro ✅ Publicados en la barra de filtros para ver únicamente los speakers que ya están marcados para la web. Esto te da una vista previa de lo que verá el desarrollador.

PARA EL DESARROLLADOR

El endpoint devuelve todos los speakers. El desarrollador debe filtrar por r[36] === 'si' (campo landing) para mostrar solo los publicados. El campo estado (r[31]) es uso interno de LABITCONF y no determina si el speaker aparece en la web. Ver tab Para el desarrollador para el detalle técnico.

Integración de Speakers — LABITCONF 2026
Guía para el equipo de desarrollo web. El listado de speakers vive en Google Sheets y se sirve vía un endpoint público de Google Apps Script (GAS). No requiere autenticación.
ENDPOINT
Hacer un GET a esta URL devuelve todos los speakers en formato JSON:
https://script.google.com/macros/s/AKfycbwe2LgPxVzFFto-fsQl0gSng2rgzbRSroALHOra43wK2QhlJZ_s-1xKHyv9An_g1ZA/exec?action=get_data&sheet=Speakers&key=BTC/2026
RESPUESTA JSON
El campo data contiene un array de arrays. La primera fila es el encabezado. Ejemplo:
{ "ok": true, "sheet": "Speakers", "data": [ ["postulacion_num", "nombre", "apellido", "confname", ...], // fila 0 = header [42, "Satoshi", "Nakamoto", "Satoshi N", ...], // fila 1 = primer speaker ... ] }

EJEMPLO DE INTEGRACIÓN (JavaScript)
const GAS_URL = 'https://script.google.com/macros/s/AKfycbwe2LgPxVzFFto-fsQl0gSng2rgzbRSroALHOra43wK2QhlJZ_s-1xKHyv9An_g1ZA/exec'; async function getSpeakers() { const res = await fetch(`${GAS_URL}?action=get_data&sheet=Speakers&key=BTC/2026`); const json = await res.json(); if (!json.ok) throw new Error('Error al cargar speakers'); // Saltar fila 0 (header), mapear a objetos return json.data.slice(1).map(r => ({ id: r[0], nombre: r[3] || `${r[1]} ${r[2]}`.trim(), // confname o nombre+apellido cargo: r[5], pais: r[6], foto: r[10], linkedin: r[14], x: r[15] ? `https://x.com/${r[15].replace(/^@/,'')}` : '', instagram: r[16] ? `https://instagram.com/${r[16].replace(/^@/,'')}` : '', website: r[9], bio: r[21], estado: r[31], web_order: r[40] ? parseInt(r[40], 10) : null, // orden en web })).filter(s => s.nombre) .sort((a, b) => { const an = a.web_order, bn = b.web_order; if (an && bn) return an - bn; if (an) return -1; if (bn) return 1; return (Number(a.id)||0) - (Number(b.id)||0); }); } // Uso: getSpeakers().then(speakers => { console.log(speakers); // array listo para renderizar });
ESTRUCTURA DE CATEGORÍAS
Los speakers están organizados en 3 categorías según el campo web_order (columna r[40] o el mapa WEB_ORDER hardcodeado):
Categoríaweb_orderOrden de presentaciónSpeakers

Categoría 249 – 84Alfabético por nombre~36
Categoría 385+Alfabético por nombre~43
Para implementar esta lógica en tu frontend:
function catOf(webOrder) { if (!webOrder) return 3; if (webOrder <= 48) return 1; if (webOrder <= 84) return 2; return 3; } const cat1 = speakers.filter(s => catOf(s.web_order) === 1); const cat2 = speakers.filter(s => catOf(s.web_order) === 2) .sort((a,b) => a.nombre.localeCompare(b.nombre, 'es')); const cat3 = speakers.filter(s => catOf(s.web_order) === 3) .sort((a,b) => a.nombre.localeCompare(b.nombre, 'es'));

NOTAS IMPORTANTES
Orden en web: Categoría 1 (posiciones 1-48) tiene orden definido por LABITCONF. Categorías 2 y 3 van en orden alfabético. El campo r[40] (web_order) tiene precedencia sobre el mapa hardcodeado.
Fotos: Las URLs de foto son de Google Drive. Funcionan directamente en <img src="...">. Para mejor rendimiento, recomendamos descargarlas y servir desde el CDN propio en producción.
CORS: El endpoint de GAS devuelve cabeceras CORS abiertas (Access-Control-Allow-Origin: *). El fetch funciona desde cualquier origen.
Caché recomendada: El endpoint puede tardar 5-15 segundos en responder (Google Sheets). Cachear el resultado por 10-30 minutos en el servidor o en el cliente con localStorage.
Filtrar para la web pública: Usar r[36] === 'si' (campo landing). Ese campo lo controla LABITCONF desde este panel. El campo r[31] (estado: confirmado/disponible) es uso interno y no debe usarse para filtrar la web.
